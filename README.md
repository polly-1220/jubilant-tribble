# ReBuildDrone

Застосунок шукає тріщини на макеті будівлі. Дрон BetaFPV Meteor75 Pro II, підключений по USB,
показує, чи його тримають рівно. Коли дрон стабільний, вебкамера Mac робить знімок, AI шукає тріщини,
людина підтверджує знахідки, а програма робить PDF-звіт і розфарбовує 3D-модель макета.

Усе працює **офлайн**: інтернет потрібен тільки один раз, щоб встановити бібліотеки.

---

## Перший запуск (macOS), крок за кроком

### 1. Відкрити Термінал у папці проєкту
Finder → права кнопка на папці проєкту → «Нові служби» → «Новий термінал у папці».
(Або відкрий Термінал і напиши `cd ` (з пробілом), перетягни папку у вікно Термінала і натисни Enter.)

### 2. Перевірити Python
```bash
python3 --version
```
Має бути `Python 3.11` або новіший (проєкт перевірено на Python 3.12).

### 3. Створити віртуальне середовище (лише один раз)
Віртуальне середовище — це окрема «коробка» з бібліотеками тільки для цього проєкту.
```bash
python3 -m venv .venv
```

### 4. Увімкнути середовище (щоразу, коли відкриваєш новий Термінал)
```bash
source .venv/bin/activate
```
На початку рядка з'явиться `(.venv)`, отже все вдалося.

### 5. Встановити бібліотеки (лише один раз, потрібен інтернет)
```bash
pip install -r requirements.txt
```

### 6. Запустити застосунок
```bash
streamlit run app.py
```
Браузер відкриється сам на адресі http://localhost:8501.
Щоб зупинити програму, натисни в Терміналі `Control + C`.

## Важливо про дрон
- Підключай дрон USB-кабелем **з передачею даних** (деякі кабелі лише заряджають).
- **Закрий або від'єднай Betaflight Configurator у Chrome** (кнопка «Disconnect»),
  інакше порт буде зайнятий і програма не зможе прочитати дрон.

## Перевірка зв'язку з дроном (без інтерфейсу)
1. Підключи дрон по USB, у Betaflight Configurator натисни «Disconnect».
2. У Терміналі (з `(.venv)` на початку рядка):
```bash
python tools/test_drone.py
```
Має з'явитися рядок, що оновлюється: крен, нахил, рискання, гіроскоп і «СТАБІЛЬНО» / «нестабільно».
Подивитися всі порти: `python tools/test_drone.py --list`.

У застосунку (вкладка «🛸 Дрон») є **демо-режим** — несправжні дані, щоб перевірити інтерфейс без дрона.

> Після зміни коду в папці `core/` перезапусти застосунок (`Control + C`, потім знову `streamlit run app.py`),
> бо зв'язок з дроном працює у фоні й тримає порт відкритим.

## ArUco-мітки для макета
```bash
python tools/make_aruco_markers.py
```
З'явиться папка `markers/` з файлом `aruco_sheet_A4.pdf`. Друкуй **у масштабі 100%**, виріж мітки
**разом з білою рамкою** і наклей на макет: ID 0–8 = сектори A1, A2, A3, B1, B2, B3, C1, C2, C3.

## Камера
- Під час першого ввімкнення камери macOS спитає дозвіл. Якщо камера не вмикається:
  Системні параметри → Конфіденційність і безпека → Камера → увімкни «Термінал»,
  потім перезапусти застосунок.
- Телефон як камера (iPhone + Continuity Camera) зазвичай має номер 1.
- Фото з телефона можна покласти в папку `data/import/` і натиснути «Імпортувати з папки»
  (формат JPG/PNG; HEIC не підтримується).

## AI-аналіз і перевірка людиною
- Розділ «🤖 AI-аналіз» → «Аналізувати нові знімки». Потім для кожної знахідки:
  «✅ Підтвердити», «❌ Відхилити» або «↩️ Скинути», і коментар.
- Число біля знахідки — **впевненість моделі, а не оцінка небезпеки**.
- Поки файлу `models/crack_seg.onnx` немає, працює **заглушка** — простий алгоритм пошуку
  тонких темних ліній (це не AI). Програма чесно пише про це.
- Як отримати справжню модель: навчити YOLO-seg в Ultralytics на фото тріщин і експортувати:
  `yolo export model=best.pt format=onnx`, потім покласти файл як `models/crack_seg.onnx`.
  Застосунок підхопить його сам (підтримуються формати YOLOv8 / YOLO11 / YOLO26).
- Час аналізу кожного кадру записується в `logs/timing.csv`.

## Обстеження, база даних і PDF-звіт
- **Обстеження** (бічна панель ліворуч) — це окрема «папка» знімків, наприклад
  «Макет школи, сторона А». Нові знімки зберігаються в обстеження, вибране зараз.
- Усі описи знімків і знахідок зберігаються в базі **SQLite** `data/rebuild.db`
  (таблиці `surveys`, `images`, `findings`). Переглянути її можна безкоштовною
  програмою «DB Browser for SQLite». Самі картинки — у `data/raw/`, `data/annotated/`, `data/masks/`.
- Розділ «📄 Звіт» → «Сформувати PDF-звіт». Файл з'явиться в папці `reports/`.
  У звіті: застереження, підсумок, схема/3D-знімок секторів, таблиця за секторами,
  картки підтверджених знахідок, окремо — неперевірені й відхилені.
- Колір сектора — за кількістю **підтверджених** тріщин: зелений 0, жовтий 1–2, червоний 3+.
- «⏱ Лог тестування» в розділі «Звіт» показує середній час аналізу кадру і формування звіту.

## 3D-двійник макета
- Розділ «🧊 3D-двійник». Обертати — мишкою, масштаб — коліщатком, «🎯 Вигляд» — повернути камеру.
- Поки файлу `models/maket.glb` немає, показано **тестовий будинок**: сектори A1–C3 на фасаді.
- Щоб показати свій макет: збережи 3D-модель у форматі **GLB** (без Draco-стиснення) як
  `models/maket.glb` і перезавантаж сторінку. Потім увімкни «✏️ Розмітка секторів»,
  вибери сектор і клікни на моделі, де він знаходиться. Розмітка зберігається у `sectors.json`.
- Колір сектора: зелений — 0 підтверджених тріщин, жовтий — 1–2, червоний — 3 і більше.
- Клік по сектору — список його знахідок. «📸 Знімок для звіту» — картинка потрапить у PDF.
- three.js (версія 0.170.0, ліцензія MIT) лежить у `ui/twin_component/three/` — інтернет не потрібен.

## Дизайн
- Кольори, шрифти й заокруглення — у `.streamlit/config.toml` (розділ `[theme]`).
- Додаткові стилі, «стікери» і жартівливі підписи — у `ui/style.py` (список `MEMES` можна дописувати).
- Шрифти **Unbounded** і **Manrope** (ліцензія SIL OFL) лежать у `static/fonts/` — працюють офлайн.
- PDF-звіт навмисно лишається строгим, без жартів.

## Структура папок
```
app.py            головний файл (інтерфейс Streamlit)
core/             «двигун»: налаштування, дрон (msp.py, drone_reader.py, stability.py), камера, AI, база, звіт
ui/               вкладки інтерфейсу (drone_tab.py, …)
tools/            допоміжні скрипти (тест дрона, генерація ArUco-міток)
models/           crack_seg.onnx (AI) і maket.glb (3D), коли з'являться
markers/          ArUco-мітки для друку
data/import/      сюди класти фото з телефона для імпорту
data/raw/         оригінальні знімки (.jpg) і їхні описи (.json: кути дрона, якість, сектор)
data/annotated/   знімки з позначеними тріщинами
data/masks/       маски тріщин
reports/          PDF-звіти
logs/             лог часу роботи (для тестування)
static/           three.js та інші файли для 3D (локально, без інтернету)
```

## Якщо щось не працює
Скопіюй **повний** текст помилки з Термінала (від слова `Traceback` до кінця) і надішли.
